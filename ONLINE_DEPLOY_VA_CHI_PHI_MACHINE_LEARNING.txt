HƯỚNG DẪN TRIỂN KHAI ONLINE VÀ LỰA CHỌN MÔ HÌNH MACHINE LEARNING
(CHI PHÍ THẤP NHẤT - HIỆU QUẢ CAO NHẤT)
Dự án: LangGraph Multi-Agent Chatbot
================================================================================

Tài liệu này giải đáp 2 câu hỏi trọng tâm:
1. Hệ thống không sử dụng API Key bên ngoài thì có thể chạy Online được không?
2. Trong các hình thức Machine Learning hiện nay, nên áp dụng loại nào để đạt 
   hiệu quả cao nhất với chi phí tài nguyên và tài chính thấp nhất?

────────────────────────────────────────────────────────────────────────────────
PHẦN 1: KHÔNG CẦN API_KEY THÌ CÓ CHẠY ONLINE ĐƯỢC KHÔNG?
────────────────────────────────────────────────────────────────────────────────

CÂU TRẢ LỜI: HOÀN TOÀN ĐƯỢC! THẬM CHÍ CÒN DỄ DÀNG VÀ ỔN ĐỊNH HƠN.

### 1. Phân biệt rõ hai khái niệm:
- "API Key" là tài khoản/mã khóa dùng để gọi sang dịch vụ thương mại của công ty 
  khác (như OpenAI, Anthropic Claude, Groq).
- "Chạy Online" là việc đưa mã nguồn Flask/LangGraph lên một máy chủ đám mây (Cloud) 
  để người dùng ở bất kỳ đâu cũng có thể mở trình duyệt truy cập qua đường link URL.

Khi bạn không dùng API Key, toàn bộ thuật toán và dữ liệu nằm trọn gói trong máy chủ 
của bạn (Self-hosted / On-Premise).

### 2. Những ưu điểm vượt trội khi chạy Online không cần API Key:
- KHÔNG PHÁT SINH CHI PHÍ TOKEN: Bạn không bao giờ phải lo nhận hóa đơn thẻ tín dụng 
  hàng triệu đồng khi có nhiều người truy cập cùng lúc.
- KHÔNG BAO GIỜ BỊ SẬP HỆ THỐNG DO HẾT HẠN NGẠCH (Rate-Limit): Các lỗi như 429 Too Many 
  Requests của Groq hay Anthropic sẽ hoàn toàn biến mất.
- BẢO MẬT TUYỆT ĐỐI: Dữ liệu người dùng và tài liệu nội bộ không bị gửi ra server 
  ở nước ngoài, hoàn toàn đáp ứng các tiêu chuẩn bảo mật doanh nghiệp.

### 3. Các nền tảng đám mây Miễn Phí (Free Tiers) tốt nhất để chạy Online:

| Nền tảng | Cấu hình Miễn Phí | Đánh giá & Khuyến nghị |
| :--- | :--- | :--- |
| **Hugging Face Spaces** | **16 GB RAM**, 2 vCPU, 50GB ổ cứng *(Free 100%)* | **LỰA CHỌN SỐ 1**: Cấu hình cực kỳ mạnh mẽ, chạy mượt cả Python, Vector Store và mô hình SLM nhỏ. |
| **Render.com** | 512 MB RAM, 0.1 vCPU *(Free Web Service)* | Rất tốt cho ứng dụng Flask + Python Logic + BM25 nhẹ nhàng. |
| **Koyeb / Railway** | 512 MB RAM, hỗ trợ Docker | Deploy tự động từ kho Git nhanh chóng. |
| **Cloudflare Tunnel / ngrok** | Chạy trực tiếp từ máy tính cá nhân | Biến laptop của bạn thành server online qua 1 câu lệnh, phục vụ demo tức thì. |

### 4. Quy trình đưa Chatbot lên Hugging Face Spaces (3 bước đơn giản):
- Bước 1: Tạo tài khoản tại https://huggingface.co
- Bước 2: Tạo Space mới, chọn SDK là **Docker** hoặc **Gradio/Streamlit/Flask**.
- Bước 3: Push toàn bộ thư mục code lên Git của Space. Nền tảng sẽ tự động build 
  và cấp cho bạn một đường link online dạng:
  `https://your-username-chatbot-langgraph.hf.space` để bất kỳ ai cũng có thể truy cập!


────────────────────────────────────────────────────────────────────────────────
PHẦN 2: LỰA CHỌN HÌNH THỨC MACHINE LEARNING TỐI ƯU NHẤT
(CHI PHÍ THẤP NHẤT - HIỆU QUẢ CAO NHẤT)
────────────────────────────────────────────────────────────────────────────────

Để xây dựng một chatbot thông minh mà không cần máy chủ GPU đắt đỏ (hàng trăm triệu 
đồng) và không cần API trả phí, kiến trúc Machine Learning được khuyến nghị áp dụng 
gồm 3 tầng sau:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. Phân loại ý định (Intent): TF-IDF + Linear SVM (Scikit-learn)           │
│    -> RAM: <30MB | Tốc độ: 1ms | Chi phí: 0đ                                │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 2. Tra cứu tri thức (RAG): Hybrid Search (BM25 + MiniLM Bi-Encoder)        │
│    -> RAM: ~150MB | Tốc độ: 10-30ms | Kích thước model: 80MB | Chi phí: 0đ │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 3. Tạo sinh câu trả lời: Extractive QA  HOẶC  SLM Quantized (Qwen2.5-0.5B)  │
│    -> RAM: 600MB - 1GB | Tốc độ: 0.5s | Chạy mượt trên CPU thường          │
└─────────────────────────────────────────────────────────────────────────────┘
```

────────────────────────────────────────────────────────────────────────────────
CHI TIẾT TỪNG TẦNG CÔNG NGHỆ MACHINE LEARNING
────────────────────────────────────────────────────────────────────────────────

### TẦNG 1: PHÂN LOẠI CÂU HỎI (INTENT CLASSIFICATION)
- **Hình thức ML:** Machine Learning truyền thống (Statistical NLP).
- **Thuật toán khuyên dùng:** **TF-IDF Vectorizer + Linear SVM (hoặc Logistic Regression)**.
- **Thư viện:** `scikit-learn`.
- **Tại sao tối ưu nhất?**
  * Không cần LLM to lớn. Chỉ cần chuẩn bị 50-100 câu mẫu đại diện cho 12 nhóm ý định 
    (`calculate`, `datetime`, `search`, `rag`, `greet`, v.v.).
  * Huấn luyện mất chưa đầy **1 giây** trên CPU.
  * Tốc độ suy luận chỉ **0.001 giây (1 miligiây)**.
  * Độ chính xác đạt **95% - 98%**, loại bỏ hoàn toàn việc tốn phí gọi LLM chỉ để phân loại.

### TẦNG 2: TRA CỨU TRI THỨC (RAG RETRIEVAL)
- **Hình thức ML:** Dense Retrieval (Bi-Encoder) kết hợp Lexical Search.
- **Mô hình khuyên dùng:** **Hybrid Search (BM25 + SentenceTransformers)**.
  * *Lexical Search (BM25):* Khớp chính xác từ khóa, thuật ngữ chuyên môn, mã code.
  * *Dense Semantic Search:* Mô hình `sentence-transformers/all-MiniLM-L6-v2` (tiếng Anh) 
    hoặc `paraphrase-multilingual-MiniLM-L12-v2` (đa ngữ / tiếng Việt).
  * *Vector Database:* `ChromaDB` hoặc `FAISS` chạy nhúng trực tiếp trong Python.
- **Tại sao tối ưu nhất?**
  * File mô hình chỉ nặng **~80 MB - 120 MB**, tải về máy 1 lần là dùng vĩnh viễn.
  * Bộ nhớ RAM chỉ chiếm khoảng **150 MB - 250 MB**.
  * Chạy cực nhanh trên CPU bình thường mà không cần card đồ họa rời (GPU).
  * Độ chuẩn xác tìm kiếm tương đương các hệ thống RAG thương mại.

### TẦNG 3: TRẢ LỜI CÂU HỎI (ANSWER GENERATION)
Bạn có 2 lựa chọn tùy theo mục tiêu của đề tài:

**LỰA CHỌN A: Extractive QA & Template Synthesis (Khuyên dùng cho đồ án ổn định)**
- Trích xuất trực tiếp đoạn văn bản chứa câu trả lời từ kết quả RAG, sau đó định dạng 
  thành cấu trúc câu rõ ràng kèm trích dẫn nguồn tài liệu.
- Ưu điểm:
  * Chi phí = 0đ, RAM tiêu thụ = 0MB.
  * Tính chính xác 100% (Zero Hallucination), không bao giờ trả lời sai lệch tài liệu.
  * Thời gian phản hồi: Gần như tức thì (<0.05 giây).

**LỰA CHỌN B: Small Language Model (SLM) thế hệ mới dạng Lượng tử hóa 4-bit (GGUF)**
- Nếu bạn muốn chatbot có khả năng đối thoại tự nhiên, linh hoạt như ChatGPT:
  * Mô hình: **Qwen2.5-0.5B-Instruct** (Alibaba, chỉ 500 triệu tham số) hoặc 
    **Llama-3.2-1B-Instruct** (Meta).
  * Định dạng: `GGUF (Q4_K_M)` chạy qua thư viện `llama-cpp-python` hoặc `Ollama`.
- Ưu điểm:
  * Kích thước file model: Chỉ khoảng **400 MB - 800 MB**.
  * RAM tiêu thụ: Chỉ khoảng **700 MB - 1.2 GB**.
  * Chạy mượt mà trên CPU của máy tính cá nhân hoặc server miễn phí (Hugging Face Spaces).
  * Vẫn tạo sinh câu văn mượt mà, tổng hợp thông tin tốt mà không tốn 1 xu chi phí API!

────────────────────────────────────────────────────────────────────────────────
KẾT LUẬN VÀ LỜI KHUYÊN CHO ĐỀ TÀI THỰC TẬP
────────────────────────────────────────────────────────────────────────────────

1. Việc cắt bỏ API Key và chuyển sang mô hình Local RAG + Pure Python/SLM là **hoàn toàn 
   khả thi để chạy Online** trên các nền tảng miễn phí như Hugging Face Spaces hoặc Render.
2. Phương án ML tối ưu nhất cho bạn:
   - **Tầng Intent:** Dùng `scikit-learn` (TF-IDF + Linear SVM).
   - **Tầng Tri thức:** Dùng `ChromaDB` + `sentence-transformers` siêu nhẹ (~80MB).
   - **Tầng Điều phối:** Dùng `LangGraph StateGraph` để quản lý trạng thái.
3. Hướng đi này giúp bài báo cáo thực tập của bạn nổi bật hơn rất nhiều: thay vì chỉ là một 
   "người dùng dịch vụ API của công ty khác", bạn trở thành một kỹ sư tự thiết kế, làm chủ 
   hạ tầng và tối ưu hóa hệ thống AI tinh gọn (Lean AI / Edge AI).
